# たなごころ 設計案（Step 1）

> ステータス: 承認待ち。承認後に Step 2（ダミー実装）へ進む。
> 判断の拠り所は常に「院ではなく、人で選ぶ。」。迷ったら「それは先生の言葉と比較項目を読みやすくするか？」で決める。

## 0. 前提の確認（依頼文の欠落）

依頼文の「なぜ星もランキングも載せな」から「ercelにデプロイ」までが欠けている。以下の仮定で設計した。違っていれば指摘してほしい。

- 欠落部分（コンセプトの反映先の続き）: 「このサイトについて」で星・ランキングを載せない理由を説明する。その他の反映先は不明。
- 技術スタック: **Next.js（App Router・SSG）+ TypeScript + Tailwind CSS、Vercel にデプロイ**

## 1. トップページのコピーと構成

### 1-1. ファーストビュー（コピーは確定文言をそのまま使う）

```
院ではなく、[人]で選ぶ。          ← h1。「人」だけ強調色。太字・特大
星も、ランキングも、ありません。
あるのは、先生本人の言葉だけ。      ← 宣言。h1の直下、中サイズ

たなごころは、整体師・鍼灸師一人ひとりを取材し、
考えと人柄を届けるメディアです。
安さや近さではなく「この人に任せたい」で
選べる出会いを増やしていきます。     ← 定義と約束。本文サイズ

[ 先生を探す ]   たなごころについて →
```

- 写真は FV に置かない。最初の画面は言葉だけにして「言葉で選ぶメディア」であることを体験として伝える。写真はすぐ下の新着カードから始まる。
- 強調色は「人」とリンク/CTA、フォーカスリングだけに使う。

### 1-2. ページ構成（上から）

| # | セクション | 見出しコピー案 | 中身 |
|---|---|---|---|
| 1 | FV | （上記） | 見出し・宣言・定義・CTA |
| 2 | 新着インタビュー | **最近、話を聞いた先生** | 先生カード6枚（顔写真＋一言＋名前・職種・エリア）。「先生をもっと見る →」 |
| 3 | 探し方 | **3つの手順で、先生を絞る** | ①読む：インタビューで考えと人柄を知る ②比べる：同じ項目で2〜3人を並べる ③会いに行く：院の連絡先は各ページに。各手順に短い説明を付ける |
| 4 | エリアから | **近くで話を聞いた先生** | 都道府県 → 市区町村のリンク（掲載がある地域だけ） |
| 5 | 職種から | **整体の先生／鍼灸の先生** | 2つの大きなリンク。整体と鍼灸の違いを各1〜2行で説明 |
| 6 | 星がない理由 | **星をつけない、と決めました。** | 3行の要約＋「このサイトについて →」 |
| 7 | 掲載について | **取材させてくれる先生を探しています** | 先生向けの小さなリンク（読者の動線を邪魔しない位置・サイズ） |
| 8 | フッター | — | ロゴ／ナビ／ポリシー／「掲載料による表示順の変更はしていません」 |

6 の文案:

> 体の感じ方も、合う手の当たり方も、人によって違います。
> 誰かの満足度の平均では、あなたに合う先生は決まりません。
> だから、点数のかわりに、先生本人の言葉を載せています。

## 2. サイトマップと URL 設計

```
/                                トップ
/sensei/                         先生を探す（一覧。新着順／エリア順＋絞り込み）
/sensei/[slug]/                  先生のインタビュー（個別）
/seitai/                         整体の先生（職種別の一覧。SEO 用の入口）
/shinkyu/                        鍼灸の先生（同上）
/area/                           エリアから探す（都道府県の一覧）
/area/[pref]/                    例: /area/tokyo/
/area/[pref]/[city]/             例: /area/tokyo/setagaya/
/clinic/[slug]/                  院の情報＋所属している先生（院の一覧ページは作らない）
/compare/?s=slug1,slug2,slug3    先生を比べる（noindex）
/about/                          このサイトについて（名前の由来・星をつけない理由・取材方針）
/about/editorial-policy/         編集・表現ポリシー（効果の書き方、掲載条件、広告の扱い）
/join/                           掲載を希望する先生へ
/privacy/                        プライバシーポリシー
/sitemap.xml  /robots.txt  /404
```

設計の判断:
- **主語が「先生」の URL を最上位にする。** `/sensei/` が軸で、院は `/clinic/` に置く。院の一覧ページとナビ項目は作らない。院ページは「この院にいる先生」を見せる受け皿。
- slug は先生ならローマ字の名前（例: `mihon-hana`）、院なら院名のローマ字。公開後は変えない。かぶったら `-2` を付ける。
- 絞り込みはクエリ（`/sensei/?type=shinkyu&concern=katakori`）で行い、`noindex` と、絞り込み前のページへの canonical を付ける。インデックスさせるのは職種別とエリア別の静的ページだけにして、薄いページを増やさない。
- **エリアページは掲載が3人以上になってからインデックスさせる**（2人以下のあいだは noindex）。
- 一覧のページ送りは `/sensei/page/2/` の静的パスにする（1ページ24人）。

### title の規則（全ページに「整体」か「鍼灸」を入れる）

| ページ | title |
|---|---|
| トップ | たなごころ｜院ではなく、人で選ぶ整体・鍼灸メディア |
| 先生一覧 | 先生を探す｜整体師・鍼灸師のインタビュー｜たなごころ |
| 個別 | 見本はなさん（鍼灸師／世田谷区）「一言」｜たなごころ 整体・鍼灸メディア |
| 職種別 | 鍼灸の先生を探す｜たなごころ 整体・鍼灸メディア |
| エリア | 世田谷区の整体師・鍼灸師｜たなごころ |
| 院 | サンプル鍼灸院（世田谷区）の先生｜たなごころ 整体・鍼灸メディア |
| about | このサイトについて｜たなごころ 整体・鍼灸メディア |

- トップ以外は末尾を「｜たなごころ 整体・鍼灸メディア」に統一する。
- ビルド時の lint で、**全ページの title に `整体|鍼灸` が含まれること**をチェックし、含まれなければビルドを失敗させる（Step 3）。

## 3. スキーマ案（Zod）

### 3-1. 先生（`content/sensei/[slug].mdx` の frontmatter）

```ts
Sensei = {
  // ── 基本
  slug: string,
  name: string,                 // 見本 はな
  nameKana: string,
  photo: { src, alt (必須・10字以上), focalPoint? },
  catchphrase: string,          // 一言。最大32字。カードと title の主役
  types: ("seitai" | "shinkyu")[],          // 職種。両方もありえる
  licenses: ("はり師"|"きゅう師"|"あん摩マッサージ指圧師"|"柔道整復師"|"理学療法士"|...)[],  // 国家資格
  otherQualifications?: string[],          // 民間資格。表示は本文中心、比較表では小さく
  startedYear: number,          // 施術を始めた年 → 経験年数は表示時に計算（古くならないように）
  clinics: { slug, role: "院長"|"スタッフ"|"業務委託", days?: string }[],  // 1人が複数の院にいる場合に対応

  // ── 比較項目（ここが判断材料の半分。順番は個別ページでも比較ページでも同じ）
  compare: {
    // A. 人
    why: string,                // この仕事を選んだきっかけ（1文・最大60字）
    // B. 考え
    belief: string,             // 施術でいちばん大切にしていること（1文・最大60字）
    approach: string,           // 不調にどう向き合うか（1文・最大80字）
    // C. 施術
    pressure: "やさしめ" | "中くらい" | "しっかり" | "相談して決める",   // 刺激の強さ
    methods: string[],          // 手技・道具（例: 刺さない鍼、せんねん灸、骨格調整なし）
    talkStyle: "静かに受けたい人向け" | "話しながら" | "合わせる",       // 施術中の会話
    explanation: string,        // 施術の前後にどう説明するか（最大60字）
    firstVisit: { counselingMin: number, treatmentMin: number },       // 初回の問診と施術の時間
    visitPace: string,          // 通うペースの考え方（最大60字）
    selfCare: boolean,          // セルフケアを教えるか
    concerns: ConcernTag[],     // よく受ける相談（決まった語彙から最大5つ）
    notFor: string,             // 【追加提案】ほかを勧めることがあるケース（最大80字）
    // D. 通いやすさ
    gender?: "女性" | "男性",   // 本人が出すことを希望したときだけ
    price: { firstVisit: number, regular: number, note? },  // 税込・円。並べ替えにも強調にも使わない
  },

  // ── 取材情報
  interviewedAt: date, publishedAt: date, updatedAt?: date, verifiedAt: date,  // 情報を確認した日
  interviewer: string, photographer?: string,
  listing: "free" | "paid",     // 将来の有料掲載に備える。paid なら「掲載プラン利用」と自動で表示（ステマ規制対策）。表示順には影響しない
  draft: boolean,
}
```

`ConcernTag` は決まった語彙（例: 肩こり・腰の重さ・頭痛・眠りの浅さ・冷え・産前産後・スポーツの体のケア・緊張しやすさ…）で `data/concerns.ts` に置く。自由入力にすると絞り込みが崩れるため。

### 3-2. 院（`content/clinic/[slug].yaml`）

```ts
Clinic = {
  slug, name, nameKana,
  kind: "整体院" | "鍼灸院" | "鍼灸整骨院" | "施術室" | "その他",
  address: { prefSlug, citySlug, line, building? },   // 都道府県・市区町村は data/areas.ts の決まった値から選ぶ（表記ゆれ対策）
  stations: { line, name, walkMin }[],
  hours: { days: ("月"|...|"日"|"祝")[], open: "10:00", close: "20:00" }[],
  hoursNote?: string,
  booking: { phone?, url?, line? },      // 予約は院の窓口に外部リンクで案内するだけ
  features: ("個室"|"駐車場"|"子連れ相談可"|"訪問施術"|"英語対応"|"バリアフリー")[],
  insurance?: "取り扱いあり(医師の同意書が必要)" | "なし",   // 鍼灸の療養費。断定的な表現を避ける
  photo?: { src, alt },   // 内観。サイト内では脇役
}
// 所属している先生は Sensei.clinics から逆にたどって組み立てる（二重管理しない）
```

### 3-3. 比較項目の過不足の提案

**追加したい項目**
| 項目 | 理由 |
|---|---|
| `notFor`（ほかを勧めることがあるケース） | 「人で選ぶ」には合わないことを知るのも大事。正直さが先生の人柄そのものになる。医療機関の受診を勧めるケースの書き方の型にもなる |
| `talkStyle`（施術中の会話） | 人柄で選ぶ読者には効いてくる。院の比較サイトにはまず無い |
| `explanation`（説明のしかた） | 「どう施術するか」の中でも、初めての人がいちばん不安なところ |
| `verifiedAt`（情報を確認した日） | 料金や営業時間が古くならないように。半年たったら確認し直す運用 |
| `gender`（任意） | 女性の先生を探す人は多い。ただし本人が希望したときだけ出す |

**載せない（または比較表に入れない）項目**
| 項目 | 理由 |
|---|---|
| 施術した人数（延べ◯万人など） | 数字の大小を比べる＝星の代わりになる。誇大な表現にもなりやすい |
| 受賞歴・メディア掲載歴 | 肩書きの比べ合いになる。触れるなら本文の中で文脈ごと |
| 「得意な症状」 | 効果をうたう表現になるおそれがあるので「よく受ける相談」と言い換える |
| 初回割引・キャンペーン | コンセプトの「やらないこと」に入る。料金は通常の額だけ |
| 院の外観写真 | 主役は先生 |

### 4-4. 比較 `/compare/`

```
┌──────────────────────────┐
│ 先生を比べる（3人）       │ h1
│ □ 違いがある項目だけ見る  │
├──────────────────────────┤
│ ┌────┬────┬────┐         │ 先生の行はスクロールしても上に固定
│ │写真│写真│写真│         │ 顔写真＋名前＋✕外す
│ │はな│一郎│…  │         │ 並びは選んだ順（優劣はつけない）
│ └────┴────┴────┘         │
│ ▸ 人                     │ 項目のまとまり（人／考え／施術／通いやすさ）
│  職種  鍼灸 | 整体 | 鍼灸 │ 短い値は横に3列
│  経験  12年 | 8年 | 20年  │
│ ▸ 考え                   │
│  大切にしていること       │ 長い文は列にせず、先生ごとに縦に積む
│   [はな] ……             │
│   [一郎] ……             │
│ ▸ 施術                   │
│  刺激  やさしめ|しっかり|… │
│  …                      │
│ ▸ 通いやすさ              │
│  エリア／駅／曜日／料金    │
├──────────────────────────┤
│ [この先生を知る] ×3       │ 各先生の個別ページへ
└──────────────────────────┘
```

- 比べる先生の選択は `localStorage` に保存し、URL（`?s=`）にも出す。URL を共有すれば同じ比較が開ける。
- **最大3人。** 4人目を選ぼうとしたら「比べられるのは3人までです」と知らせる（`aria-live`）。
- 最大値・最小値に色を付けたり「おすすめ」を付けたりはしない。どの値も同じ見た目で並べる。
- 比較ページは `noindex`。データは全先生の比較項目だけを抜き出した JSON（ビルド時に作る）から読む。数百人になっても数百 KB 以内に収まる。

## 5. コンテンツ管理の比較と推奨

| 観点 | **MDX + frontmatter + Zod**（第一案） | microCMS | Sanity |
|---|---|---|---|
| 入稿する人 | Git を使える人だけ | 非エンジニアでも可（日本語の画面） | 非エンジニアでも可（画面を作り込む必要あり） |
| スキーマの検証 | Zod でビルド時に止められる。いちばん強い | 画面での必須チェック＋取り込み時に Zod | スキーマを細かく書ける＋取り込み時に Zod |
| 本文の表現 | MDX の部品（Quote/Photo）を自由に使える | リッチエディタ（部品はカスタムフィールドで工夫） | Portable Text（部品を作れる。移行しやすい） |
| 画像 | リポジトリに置く。数百人×複数枚だと重い | 画像 CDN（変換付き）が付く | 画像 CDN（変換付き）が付く |
| 下書き・プレビュー・公開予約 | PR のプレビュー（Vercel）で代わりにする | あり | あり |
| 費用 | 0円 | 無料枠あり。件数と人数で有料 | 無料枠あり。人数で有料 |
| 先生本人による情報更新 | できない | 権限を分ければできる | できる |
| 乗り換えにくさ | なし | 中 | 中 |

**推奨: MDX + Zod で始め、データを読む層（`lib/content/`）を1か所にまとめておく。**

- ページ側は `getAllSensei()` `getSensei(slug)` `getClinic(slug)` だけを呼ぶ。中身を CMS に差し替えてもページは変えなくてよい。
- Zod スキーマは CMS に移ってもそのまま「入口の検証」として使い続ける。
- MDX で使う部品は `Q` `Quote` `Photo` の3つに限る。CMS のリッチテキストに機械的に変換できる範囲にとどめるため。
- **乗り換えの目安**（どれか1つに当てはまったら）: 掲載が約80人を超えた／Git を使えない編集者が入った／先生本人に料金や営業時間を直してもらいたくなった／画像がリポジトリを圧迫し始めた。
- 乗り換え先は日本語で入稿する編集体制なら **microCMS**。本文の部品を増やしていくなら Sanity。

## 6. 表現ルール：NG ワードの初期リスト案

lint で2段階に分ける。**error = ビルドを止める／warn = 編集者が確認する**。否定の文脈（例:「治る、とは言いません」）は行ごとに `{/* ng-ok: 治る 理由 */}` で許可できるようにする。

### A. コンセプトに反する（error）
ランキング／第◯位／No.1／ナンバーワン／人気順／おすすめ順／人気の先生／口コミ／評判／レビュー／★／星◯つ／満足度◯%／点数／最安／格安／激安／お得／割引／半額／初回◯円／キャンペーン／クーポン／名医／神の手／ゴッドハンド／カリスマ／院を探す

### B. 効果を言い切る・医療と誤解させる（error）
治る／治す／完治／根治／根本治療／必ず良くなる／絶対／100%／確実に／即効／1回で／二度と（痛く）ならない／副作用なし／痛くない（言い切り）／診断／処方／医師も推薦／病院で治らない／◯◯が消える／免疫力が上がる／若返る／痩せる
- 「治療」は整体の先生の文脈では error、鍼灸では warn（判断が要るため）。

### C. 優位性・他院との比較（error）
日本一／業界初／唯一の／最高の／最先端／他院とは違う／他院では／◯◯より効く

### D. 不安をあおる（warn）
放置すると危険／手遅れ／このままでは／今すぐ

### E. 注意して使う（warn）
改善／根本改善／自律神経を整える／骨盤のゆがみ／姿勢が良くなる／デトックス／代謝が上がる／患者さんの声／体験談／ビフォーアフター

> 法的な前提として、鍼灸の広告は「あはき法」の第7条で載せてよい事項が限られている（対象は「何人も」）。整体は国家資格ではないが、医師法や景品表示法との関係に注意が要る。また、有料掲載を始めるとステマ規制（2023年10月から）の対象になる。編集記事として作っていても、院への予約導線を持つ以上は広告とみなされるおそれがある。**公開前、遅くとも有料掲載を始める前に、専門家（弁護士など）による確認を勧める。** このリストはあくまで初期案。

## 7. デザインの方針とロゴ案

### 7-1. 基本
- 白地（#FFFFFF）、文字は墨色（#1A1A1A）、補助の灰色は #5C5C5C（白地でコントラスト比 6.6:1）。
- **強調色は1色だけ。** 候補は2つ（どちらも白地で AA を満たす）
  - 朱（#B4321E 前後）: 手のぬくもりや血色。「人」がいちばん目立つ
  - 藍（#23407A 前後）: 落ち着いていて、医療っぽくならない
- 見出しは太いゴシック（例: Zen Kaku Gothic New Bold）。本文 16〜17px、行間 1.9、1行の長さは最大38字前後。
- 余白は 8px 単位で、セクションの間はモバイル 72px／PC 128px。
- アクセシビリティ: フォーカスリングをはっきり出す／「比べる」ボタンは `aria-pressed`／比較表は `th scope`／写真の alt はスキーマで必須／動きは `prefers-reduced-motion` に従う。

### 7-2. ロゴ案（文字組み）

**案A ― 横組み・太ゴシック・字間を詰める（推奨）**
```
たなごころ
```
- 書体: 太いゴシック（Zen Kaku Gothic New Black 相当）、字間 0.02em
- 見出しの太いゴシックと同じ声で、ヘッダーで小さくしても読める
- 強調色は使わない（墨1色）。小さく「整体・鍼灸メディア」を添えた版も作る

**案B ― 横組み・明朝・字間を大きく空ける**
```
た　な　ご　こ　ろ
```
- 書体: 明朝の太め（Shippori Mincho B1 Bold 相当）、字間 0.3em
- 間（ま）があって手仕事の静けさが出る。ただし小さくすると間延びし、見出しのゴシックと声が分かれる

**案C ― 縦組み・明朝（補助ロゴ）**
```
た
な
ご
こ
ろ
```
- 書体: 明朝、字間 0.15em。「ご」の濁点だけを強調色にした版も試す
- 使いどころ: OGP 画像、about ページ、印刷物、PC での縦の差し込み。ヘッダーには案Aを使う

推奨: **ヘッダーは案A、OGP と about ページで案Cを補助に使う。**

## 9. 確認したいこと

1. **依頼文の欠落**: 「なぜ星もランキングも載せな…」から「…ercelにデプロイ」までの間に、何が書いてあったか。技術スタックは Next.js + TypeScript + Tailwind + Vercel で合っているか。
2. **収益モデル**: 【例: …】のままになっている。「当面は無料で掲載し、将来は掲載プランと予約送客」で確定でよいか（`listing` 項目と「掲載料はいただいていません」の表示に関わる）。
3. **強調色**: 朱と藍のどちらにするか（ほかの色の希望でもよい）。
4. **ロゴ**: 案A＋案C（補助）で進めてよいか。
5. **料金**: 比較項目に通常の額だけを載せる（並べ替え・強調はしない）案でよいか。載せないという選択肢もある。
6. **「よく受ける相談」で絞り込む機能**: 入れてよいか。読者には便利だが、効果をうたっているように読まれないよう言葉に気をつける必要がある。
7. **院ページ**: `/clinic/[slug]/` を独立したページとして持つ（院の一覧とナビ項目は持たない）案でよいか。
8. **初期の対象エリア**: 全国か、特定の地域から始めるか（エリアページの作り方と、エリア順の並び方に関わる）。
9. **ダミー写真**: プレースホルダー（色面＋イニシャル）でよいか、それとも画像を生成して顔写真が主役の見た目まで確認したいか。
10. **ドメイン**: 決まっていれば（canonical と OGP に使う）。未定なら仮の値で進める。
